# Social Content

Create social content that fits the intended audience, the platform, and the user's purpose.

## Context and Scope

Use the supplied topic, source material, examples, and relevant project context. Read `.claude/product-marketing-context.md` if it exists and product background would help this request.

For one post or a short rewrite, infer tone and audience where reasonable and produce the draft. Ask only when missing information would materially change the result and cannot be inferred. Mention assumptions when they affect how the draft should be evaluated.

For a content strategy or calendar, use these as optional context prompts:

- Objective and desired audience action.
- Audience and relevant platforms.
- Brand voice, topics to avoid, and examples.
- Available source material, production capacity, and performance data.

Use existing answers and reasonable assumptions. These prompts are not a required intake questionnaire.

## Content Decisions

- Lead with a concrete observation, useful information, or the requested announcement.
- Adapt length, structure, and media suggestions to the chosen platform and requested format.
- Preserve the source's meaning and credit borrowed ideas when appropriate.
- Never invent personal experiences, quotes, customer outcomes, statistics, endorsements, or product capabilities. Use factual placeholders only when the requested draft needs missing evidence, and label them clearly.
- Follow project writing rules. Templates and hooks are optional examples; they do not justify canned transitions, unsupported claims, or invented controversy.
- Add a question or CTA when it serves the user's purpose.

Return one finished post for a single-post request. Add variants, rationale, a calendar, or a broader strategy when requested or needed to complete the agreed deliverable.

## Strategy and Calendars

When requested, choose content themes that connect audience needs to the user's expertise and goals. Set cadence using production capacity and available audience data. Treat posting times, frequency, format choices, and distribution tactics as hypotheses to test; avoid universal algorithm claims.

For repurposing, adapt the requested source to the requested destinations. For a calendar, include publish dates or cadence, topics, formats, and production requirements at the level the user needs.

Assess performance against the stated objective. Distinguish reach and engagement from conversions, and explain missing data or confounding factors before attributing a result to a particular tactic.

## Optional References

Read only the reference needed for the current task:

- [Platform considerations](references/platforms.md): Choosing formats or adapting content between platforms.
- [Post templates](references/post-templates.md): Developing a structure when the supplied material needs one. Use only relevant parts and verified facts.
- [Content pattern analysis](references/reverse-engineering.md): When the user requests creator or post analysis; scale the sample and effort to the question.

Check current platform documentation when the task depends on changing limits, scheduling capabilities, or ranking behavior. Use the available tools and project retrieval rules.

Drafting a post or calendar does not authorize publishing, scheduling, commenting, reposting, or sending messages. Execute those actions only within explicit user authorization and with an available tool. A request to schedule content should use the actual destination and timing; it should not silently become a general strategy task.

Use another available skill only when its capability is needed to complete the requested work.
